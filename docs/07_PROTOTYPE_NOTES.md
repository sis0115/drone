## 2. 반드시 그대로 옮겨야 하는 것

### 2.1 렌더 파이프의 3버퍼 구조
프레임 프리즈·코덱 잔상·모션블러가 **모두 이 구조에 의존**한다. 단순 1패스 후처리로 바꾸면 현장감의 핵심이 사라진다.
```
씬 → rtA
rtA + rtPrev → 합성 셰이더 → 화면
프리즈 아닐 때만 rtA → rtPrev 복사   ← 프리즈 = 이전 프레임 유지
```

### 2.2 신호 품질 단일 변수 — **구조는 T2에서 만들어야 한다**
거리·LOS·재밍이 하나의 값으로 수렴하고 후처리 전 효과가 여기에 반응한다는 개념은 맞다.
다만 프로토타입에는 **그런 인터페이스가 존재하지 않는다.** 실제로는 게임 루프 안(`loop()` 내부)에
`sig` / `sigSmooth` 지역 변수로 인라인되어 있다:

```
const dist = Math.hypot(st.px, st.pz);
let sig = 1 - Math.max(0, dist-160)/(900/max(0.2, P.falloff));
sig -= losBlock*0.55;
if (jam) sig -= 0.45;
sigSmooth += (sig-sigSmooth)*min(1, dt*6);
```

이대로 옮기면 **v0.5 EW 시스템이 조작할 지점이 없다.** T2에서 계산식(위 4줄)은 그대로 보존하되,
`SignalModel` 같은 모듈로 빼서 입력(거리·LOS·재밍 소스)과 출력(`quality`)을 인터페이스로 만들 것.
위협 카탈로그 B계열(재밍 돔·스푸핑·역추적)이 전부 여기에 붙는다.

### 2.3 열화상 = 머티리얼 스왑
셰이더 밝기 리맵으로는 4단 구조(하늘 흑 / 물 흑 / 지면 명 / 열원 백열)가 나오지 않는다. 오브젝트마다 열값을 부여하고 모드 전환 시 머티리얼을 교체하는 방식을 유지 (02 문서 4.4 테이블).

### 2.4 배럴 왜곡 ↔ 오버레이 좌표 역변환
셰이더에서 `uv = 0.5 + c*(1 + k*r²)` 로 왜곡하면, SVG 마커도 `d = 0.5 + c*(1 - k*r²)` 로 보정해야 락온 박스가 표적에 붙는다. **둘 중 하나만 고치면 즉시 어긋난다.**

### 2.5 인스턴싱
02 문서 5장 참조. 개별 Mesh 생성 시 드로우콜 1,940 (실측). 반드시 InstancedMesh + `setColorAt` 색 변화.

## 4. 알려진 미해결 항목

- **실기 fps 미측정** — 폰 브라우저에서 60fps 확인 필요. 미달 시 조정 순서: 풀 인스턴스 수 → 그림자 해상도 → 덤불 수
- **화면 감성 파라미터 미확정** — 튜닝 패널의 프리셋 A(아날로그)/B(디지털)/C(혼합) 중 최종안 미선정. 확정 시 `src/data/postfx.ts`에 고정
- **사운드 전무** — GDD 6.5.2의 3종(확인킬음/SP틱/유폭)이 최우선
- **에셋 없음** — 전부 프로시저럴. 실사 텍스처 도입은 재미 검증 이후
- **텍스처 타일링** — 정점 컬러로 완화했으나 저고도에서는 여전히 반복이 보임
- ~~수목선(treeline) 미반영~~ → **T2 에서 반영** (`Vegetation.band()`, 도로변 2줄 + 들판 사선 2줄)
- ~~통나무 중복 생성~~ → **T2 에서 제거.** 프로토타입은 통나무를 개별 Mesh 45개 + 인스턴스 50개로
  **두 번** 만들었다. 앞쪽 45콜은 시각적으로 중복이고 순수 낭비였다 (드로우콜 116 → 62 의 주원인)
- **아케이드 모드에 바람이 없다** — 프로 모드 물리(`physics`)에는 `wind.x/z + gust` 가 들어가지만
  `physicsArcade` 에는 없다. GDD 4장이 바람을 4대 제약으로 규정했고 캠페인 2차수가 바람으로 난이도를
  올리는 구조이므로, **기본 모드인 아케이드에 바람이 없으면 그 설계가 성립하지 않는다.** T3에서 결정할 것
  (아케이드에도 약하게 넣을지, 어시스트 단계로 가를지)

## 5. 헤드리스 검증 도구 사용법

```bash
node tools/harness.js       # 프로토타입 씬 생성 에러 검출
node tools/perf.js          # 프로토타입 드로우콜/삼각형 실측
node tools/scene-check.mjs  # **코드베이스** 드로우콜/삼각형 실측 (npm run scene)
node tools/compare-demo.mjs # 둘을 같은 조건으로 렌더해 스크린샷 2장 (npm run compare)
```
`tools/`의 두 스크립트는 **DOM/캔버스를 스텁으로 대체**해 브라우저 없이 Three.js 코드를 실행한다.
코드베이스로 옮긴 뒤에도 같은 방식으로 유지하면, 브라우저를 띄우지 않고 대부분의 씬 에러를 잡을 수 있다.
(단, 실제 렌더 결과·셰이더 컴파일은 Playwright로 확인해야 한다.)
